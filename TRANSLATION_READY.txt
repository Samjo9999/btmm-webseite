ARCHITECTURE OVERVIEW
================================================================================

Translation Pipeline:

German PDFs (in DE folder)
    ↓
extract text using pdfplumber
    ↓
send to Claude API (Opus 4.1)
    ↓
domain-aware translation (terminology preserved)
    ↓
language-specific formatting applied
    ↓
output translation files (.txt)
    ↓
manual PDF conversion (text → PDF)
    ↓
quality assurance & testing
    ↓
organized by language folder
    ↓
ready for deployment/download

DESIGN DECISIONS:
- Language folders (vs. filename convention) - scales better
- Claude API (vs. Google Translate) - better domain awareness
- Semi-automated workflow - balances speed with quality
- Separate _Translations folder - original files untouched

TERMINOLOGY PRESERVATION
================================================================================

Key Terms to Maintain Across All Languages:

GERMAN → ENGLISH MAPPINGS
"Back to Balance" → keep English brand name
"BtB" → keep as acronym
"Körperarbeit" → "bodywork" (EN), "travail corporel" (FR), etc.
"Genossenschaft" → "cooperative"
"Handwerk" → "crafts" or "artisanat" (FR)

LANGUAGE-SPECIFIC NOTES:
- English: Maintain brand name "Back to Balance"
- French: 15-20% longer, formal tone
- Spanish: Use formal register (usted)
- Chinese: 20-30% more space needed
- Japanese: 50-60% more vertical space
- Arabic: RTL text direction
- Russian: Cyrillic, 10-15% longer
- Hindi: RTL, Devanagari script
- Bengali: RTL, special script

"PDF text not extracted"
→ Some PDFs may be scanned images - use OCR tool

"Translation quality poor for specific language"
→ Edit system prompt in translate_documents.py for that language

"Script hangs or times out"
→ Network issue or rate limiting - retry later
